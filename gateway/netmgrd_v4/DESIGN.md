# netmgrd_v4 — 部分重设计要纸

本文档是协作起点，**可改**。实现时以代码与 `README` 为准。

## 1. 目标

- 多 WAN/多接口：以太、WiFi STA、PPP/LTE 等
- 统一 **业务出口**：默认路由与活跃接口决策可预期、可观测
- 长期运行稳定：**不**在周期路径上无界 spawn `wpa_supplicant` / `udhcpc` / `pppd`（启动必须幂等）
- 状态落盘或对外：`status` 的语义与 `schema` 显式化

## 2. 与 v3 的切割

- 不沿用 v3 的模块边界命名与头文件，避免“修修补补又三年”
- 接受从头写：配置模型、主循环、探测/健康/切换分层接口先定 **契约** 再写实现

## 3. 建议分层（逻辑）

| 层 | 职责 | 注 |
|----|------|----|
| Config | 解析、校验、默认项 | 后续可 JSON + cjson 或更轻量格式 |
| Runtime | 每拍调度、时间、信号 | **唯一** 主循环 |
| Link | L1/L2：carrier、IPv4 地址是否存在 | 每拍或子采样 |
| Path | L3：连通性，节拍与 `active` 解耦，避免自激 | 可 ICMP，策略路由/MARK 需与系统策略一致，否则勿假设 |
| Health | 去抖动，**有界计数** | 不绑定“探测间隔是否随 state 变”的耦合 |
| Route | 默认路由与 metric | 切换可带 **滞回/最短驻留**（需单独产品决策） |
| Adapter | 启停/恢复，**idempotent start** | 与 Runtime 的 trigger 点明确列出来 |

## 4. 主循环一帧（草图）

1. 读时钟；可选：合并配置重载
2. 按接口：`Link` 更新
3. 按接口/节拍：`Path` 若本拍不探测则**显式不喂 Health**（与“SKIP”语义在文档中写清）
4. `Health` 仅收“本拍有样本/无样本”的明确定义
5. `Route` 在全局上下文上决策一次
6. `Adapter` 仅在**列出的条件**下调用（保活/恢复/人工策略），**禁止**在不明条件下每拍 `start` 全家桶
7. 输出状态（JSON/日志/LED 等，另表）

## 5. 未决（你来拍板或后续迭代）

- 配置文件路径与 `schema` 版本号
- `switch` 是否启用最短驻留、与 priority 的抢占关系
- WiFi/PPP 是 **全托管** 还是与外部脚本/NetworkManager/厂商栈协同
- 是否内置 cJSON 或外链 `-lcjson`

## 6. 目录约定

- `include/netmgr_v4.h` — 对外 API 与类型
- `src/main.c` — 入口与以后的主循环
- 新增模块时**单独** `.c`，避免再出现一个 600 行 `main.c`
