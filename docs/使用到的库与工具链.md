# 使用到的库与工具链

应用和根文件系统统一按 **ARM Cortex-A7、硬浮点、glibc** 编译。库版本取自当前 `buildroot/.config` 里已启用的包，以及应用目录里随源码带入的第三方代码。版本对应 package makefile 中的配方，不是对已安装 `.so` 做 `strings` 核对。

统计范围：顶层 `Makefile` 实际参与编译的应用（`application/gateway`、`application/meter`）、内核、驱动、U-Boot，以及 `buildroot/.config` 中启用的软件包。`application/gateway/old/`、`ref/`、`application/simple` 不进入默认镜像，下文仅在有差异时点出。

## 工具链

| 用途 | 编译器 | 目标 |
| --- | --- | --- |
| 应用、内核 5.4.61、驱动、Buildroot 软件包 | GCC **14.4.0**，前缀 `arm-buildroot-linux-gnueabihf-`，安装在 `/opt/buildroot-gcc-gnueabihf14.4.0` | `armv7-a` / Cortex-A7 / VFPv4-D16 / hard-float / ARM 指令集 |
| U-Boot 2018.05 | Linaro GCC **7.2.1**（2017.11），前缀 `arm-linux-gnueabi-`，路径 `tools/toolchain/gcc-linaro-7.2.1-2017.11-x86_64_arm-linux-gnueabi` | `arm-linux-gnueabi`（软浮点 EABI） |

Buildroot 是 **2026.05.1**，使用内部工具链（`BR2_TOOLCHAIN_BUILDROOT`）。配套组件：

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Binutils | 2.45.1 | |
| glibc | 2.43-45-gdae425b55420 | 提交快照，不是正式发行号 |
| Linux 头文件 | 5.4.61 | 与 `linux/Makefile` 中的内核版本一致 |
| C++ | 启用 | 未开 OpenMP |
| 库形态 | 仅动态库 | `BR2_SHARED_LIBS` |
| 优化 | `-O2`，链接后 strip | 未开 LTO |
| 加固 | PIE、`-fstack-protector-strong`、Full RELRO、`_FORTIFY_SOURCE=1` | |

目标三元组参数（`buildroot/.config`）：

- ABI：`aapcs-linux`
- CPU：`cortex-a7`
- FPU：`vfpv4-d16`
- 浮点 ABI：`hard`
- 指令模式：ARM（未使用 Thumb2）

顶层 `Makefile` 把内核、驱动的 `CROSS_COMPILE` 写成绝对路径 `/opt/buildroot-gcc-gnueabihf14.4.0/bin/arm-buildroot-linux-gnueabihf-`，避免 PATH 里同名前缀的 GCC 11 被用上。U-Boot 单独走 Linaro 7.2.1。根文件系统软件包由 Buildroot 自己的 `output/host` 工具链编译，配置与上述 GCC 14.4.0 一致。

有一批 gateway 采集插件仍写死旧路径：编译器 `arm-buildroot-linux-gnueabihf-gcc`（不带 `-14.4.0`），sysroot 为 `/opt/buildroot-gcc-gnueabihf/`。包括：

- `application/gateway/sampling/` 下各协议库
- `sampling_cs104`、`sampling_opc_ua`
- `edge_alert`、`iobridge`

其余 gateway 进程和 meter 侧已指向 `/opt/buildroot-gcc-gnueabihf14.4.0`。

### 头文件与链接库版本不一致

应用源码树里的头文件和实际链接的库不是同一版：

| 头文件 | 声明版本 | 实际链接（sysroot） |
| --- | --- | --- |
| `application/*/lib/sqlite3.h` | 3.30.1 | SQLite 3.53.2 |
| `application/*/lib/cJSON.h` | 1.7.12 | cJSON 1.7.19 |

这些 `lib/` 目录里只有头文件，没有对应的 `.so`。`db_process` 虽写了 `-L./lib`，真正链上的仍是 sysroot 里的 3.53.2 / 1.7.19。

## 随应用源码编进去的库

| 库 | 版本 | 编译方式 |
| --- | --- | --- |
| CMSIS-DSP | 1.16.2 | 不走自带的 `armclang` / Cortex-M55 Makefile。`measure_process` 把源文件直接编进 `measure_process_rn7302`：`gcc-14.4.0 -g -O2 -mcpu=cortex-a7 -mfpu=neon-vfpv4 -mfloat-abi=hard -ffast-math -fPIC -DARM_MATH_NEON`，链接加 `-lm -pthread -Wl,--gc-sections -flto` |
| CMSIS-Core | 6.1 | 只用头文件（`cmsis-core/include`） |
| lib60870 | 2.3.3（`LIB60870_VERSION_*`） | 预编译 `liblib60870.so`，打包时拷到 `/usr/lib`。`iec104_slave`、`sampling_iec104` 用 `-llib60870` 链接。仓库里没有它的编译规则 |
| 协议插件 | 工程自有代码 | `gcc -fPIC -shared` 生成 `libmodbusRTU.so`、`libmodbusTCP.so` 以及 DL/T645、IEC101、CJT188、DL/T698 等 `.so`。这批 Makefile 仍指向旧 sysroot `/opt/buildroot-gcc-gnueabihf`，优化级别是 `-O0` |

CMSIS-DSP 自带 Makefile 的编译器是 ARM Compiler 6.18（`armclang`，Cortex-M55），本工程未使用该规则。
